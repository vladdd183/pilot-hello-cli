# Research q2 — CI pytest strictness and `agent` → PR auto-merge

Question (from `specs/01M3C3BFZYPCEART8NFS1B90KJ/questions.yaml` lines 22–31): how GitHub Actions must change so pytest is green only when tests pass, and how an issue labeled `agent` yields a PR with auto-merge on green CI after S7.

## 1. Current CI behavior (bootstrap)

**File:** `.github/workflows/ci.yml` (worktree at `e416e60`)

Triggers and runner (lines 1–8):

```yaml
name: ci
on:
  push:
    branches: [main]
  pull_request:
jobs:
  test:
    runs-on: ubuntu-latest
```

Install step masks failures (lines 14–19):

```yaml
      - name: Install
        run: |
          if [ -f pyproject.toml ]; then
            pip install -e ".[dev]" 2>/dev/null || pip install -e . || true
          fi
          pip install pytest || true
```

Test step skips pytest when no tests exist (lines 20–26):

```yaml
      - name: Test
        run: |
          if [ -d tests ] || ls test_*.py >/dev/null 2>&1; then
            pytest -q
          else
            echo "no tests yet — ok for bootstrap"
          fi
```

**Implications:** (a) `pip install` can fail and the job still succeeds; (b) with no `tests/` and no `test_*.py`, the job prints `no tests yet — ok for bootstrap` and exits 0 without running pytest; (c) when tests exist, `pytest -q` is not wrapped in `|| true`, so failing tests should fail the job—once the bootstrap branches are removed.

**Recall alignment:** `specs/01M3C3BFZYPCEART8NFS1B90KJ/recall.md` lines 15–18, 35, 45 state the same gaps and recommend dropping the missing-test success path and install `|| true`.

## 2. Required CI changes (pytest green ⇔ tests pass)

After S5 core adds `pyproject.toml`, package, and `tests/`:

| Change | Rationale |
|--------|-----------|
| Remove `\|\| true` from `pip install` lines | Install failure must fail the job before pytest runs. |
| Remove the `if [ -d tests ] … else echo …` branch | Always run `pytest -q` (or `python -m pytest -q`) so missing or broken tests fail CI. |
| Keep `pytest -q` without `\|\| true` | Pytest non-zero exit fails the step (default GitHub Actions behavior). |
| Optional: `pip install -e ".[dev]"` only when `pyproject.toml` defines `[project.optional-dependencies] dev` with pytest | Matches PEP 621 dev extra pattern from q1 hints. |

**Minimal target Test step (conceptual, not applied on this research card):**

```yaml
      - name: Test
        run: pytest -q
```

**GitHub Actions reference:** workflow jobs fail when a step returns non-zero; pytest exits non-zero on test failures.  
URL: https://docs.github.com/en/actions/using-workflows/workflow-syntax-for-github-actions#jobsjob_idsteps

**Pytest:** `pytest -q` quiet mode — https://docs.pytest.org/en/stable/reference/reference.html#command-line-flags (`-q` / `--quiet`).

**Branch protection (repo settings, not in tree yet):** require the `ci` workflow (or required status check name) on `main` before merge so auto-merge waits for green CI.  
URL: https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches#require-status-checks-before-merging
